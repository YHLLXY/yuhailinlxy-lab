## 1. 内容来源

本页 11 个场景来自本地速查表 `E:\homework\开发\特效存储\12-自建速查\动效时长与节奏参考.md` 的「时长基准表」，
与计划里的「11 个场景」一致（逐条核对：hover / 开关 / Tooltip / 下拉 / Modal / Drawer / Tab / 列表 FLIP / 路由转场 / 骨架屏 / 数字滚动）。

## 2. 外部交叉验证：Material 3 时长 token

来源：`material-components/material-web` → `tokens/versions/v0_192/_md-sys-motion.scss`
（**Apache-2.0**，只取数值——数值是事实，不复制代码）

| 档位 | 值 |
|---|---|
| short1–4 | 50 / 100 / 150 / 200 ms |
| medium1–4 | 250 / 300 / 350 / 400 ms |
| long1–4 | 450 / 500 / 550 / 600 ms |
| extra-long1–4 | 700 / 800 / 900 / 1000 ms |

**对照结果**：我们速查表里的 11 个数字几乎全部落在 Material 的档位上（详见 `src/data/timing.ts` 的 `material` 字段）。
这说明这套经验值不是拍脑袋，和一线设计系统的节奏是同一套。

例外是骨架屏（1500ms）和数字滚动（900ms）——它们是**循环动画与数值动画**，不属于状态过渡，
Material 的 token 体系不覆盖这类，所以没有对应档位，这是合理的。

## 3. 页面设计取舍

- **用「三档并排」代替「逐个复刻 UI 图案」**：同一场景演示 过快 / 基准 / 过慢 三版，
  三条同时起跑。时长才是本页的主题，复刻 11 种真实控件只会把注意力从「多久」转移走。
- **动画属性只用 transform + opacity**：本页自己也得守性能红线，所以是 `translateY` + `opacity`，
  不做 width/left 动画。
- **同帧起跑**沿用 M2 的做法：同一个任务内写 transition。
- **Stagger 对比**：左侧 0ms 齐发，右侧 60ms 错峰，一个按钮同时启动。
